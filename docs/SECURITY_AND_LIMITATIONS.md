# Security, scope and production gates

## Publication boundary

This repository is a sanitized, reusable copy of a demonstration project. It does not carry the original tenant, workspace, SQL host, app URL, service registrations, raw source exports or deployment registry.

All committed CSV records are generated by `scripts/create-demo-data.mjs`. `.invalid` contact and policy addresses are deliberate nonworking examples. Placeholder IDs do not identify deployed resources.

Repository visibility is not application authorization. A repository clone grants no access to Fabric, Dynamics 365, SharePoint, Databricks, a published agent or M365 Copilot.

## Access paths are separate

| Path | Identity / control | Important limitation |
|---|---|---|
| Local snapshot | Local loopback server and generated CSVs | No end-user sign-in or RLS |
| Offline HTML | Complete embedded snapshot | No security boundary after download |
| Local live SQL | Azure CLI identity on the host computer | Not per-browser-user authorization |
| Fabric App | Fabric sign-in and delegated SQL connector; authenticated read-only entities | Requires source permissions and real row/field policies |
| Power BI | Semantic-model permissions and any configured RLS/OLS | Model rules do not secure a separate direct-SQL route |
| Data Agent / M365 | Configured agent/source access in the supported integration | Sharing an agent is not a grant to all underlying data |

Neither a UI filter, hidden column, prompt instruction nor anonymous HTTP 401 proves customer-specific isolation. Workspace Admin/Member/Contributor accounts are unsuitable for proving Power BI consumer RLS/OLS restrictions.

No complete customer-specific RLS, sensitive-column policy or cross-route isolation test is supplied. Do not expose real customers' data until those controls are enforced and tested.

## What this implementation does not do

- No approvals, CRM writeback, email sending or autonomous actions.
- No LLM/Data Agent invocation from the app.
- No production-managed Dataverse ingestion; the optional worker depends on a computer and CLI session.
- No live SharePoint feed or live Databricks numeric-score feed.
- No calibrated churn model or demonstrated causal link between SLA breaches and churn.
- No measured ROI, production load target, response SLA, availability SLA or recovery guarantee.
- No automatic provisioning of semantic models, Power BI reports, ontologies, shortcuts or mirrors.
- No guarantee that copies already exported can be revoked remotely.

## Production acceptance gates

1. Approve the business purpose, audience and source-data handling.
2. Replace prepared inputs with governed source integrations and stable-key contracts.
3. Define measurable freshness and reconciliation checks, including propagation latency.
4. Implement least privilege, managed identities where appropriate and source-enforced row/field restrictions.
5. Test two restricted users and an unauthorized user across app queries, agent queries, direct SQL, model totals, child tables and exports.
6. Evaluate agent answers, ambiguous requests, unsupported questions, prompt injection and provenance.
7. Add controlled release, rollback, monitoring, incident response, retention and recovery.
8. Measure concurrency, capacity consumption and all relevant license/preview requirements.
9. Review external-user support, regional processing, Copilot terms and compliance with the responsible teams.
10. Add an approval, audit and failure-handling layer before connecting any action tools.

## Dependency and configuration hygiene

Use the checked-in lock file and the supported runtime. Reassess dependency advisories before production; a passing test suite is not a vulnerability assessment.

Keep actual configuration, credentials, connector discovery metadata, deployment registries and extracted data out of Git. The app intentionally has no embedded developer credentials. A publishable client key is not a developer access token, but the original environment's registry is still excluded.

Do not resolve authorization errors by granting broad workspace administration or changing delegated access to owner/application identity.
